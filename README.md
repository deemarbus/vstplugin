# QuadTable

QuadTable is an early JUCE/C++ VST3 instrument prototype for a four-oscillator wavetable synth.

## Current prototype

- JUCE 8/CMake project that builds a VST3 and standalone instrument.
- 16-voice polyphonic MIDI synth engine.
- Four wavetable oscillators per voice.
- Per-oscillator level, pan, coarse tune, fine tune, and wavetable position parameters.
- Amp ADSR and filter ADSR.
- One state-variable low-pass filter per voice.
- Initial modulation-matrix data model for adding flexible routing in later milestones.
- Generic JUCE parameter editor for fast iteration.

## Build

### Quick diagnosis

If the plugin build does not work locally, run:

```bash
./Scripts/diagnose_local_build.sh
```

The script checks whether CMake, a C++ compiler, Git, and a usable JUCE checkout can be found.

### Core-only build, no JUCE required

The default configure path is network-free, so it works even when the environment cannot clone JUCE from GitHub. Without JUCE it builds `QuadTableCore` and a smoke-test executable for the wavetable oscillator core:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build --output-on-failure
```

### Plugin UI build with local JUCE

To build and view the real VST3/Standalone plugin UI, JUCE must be available locally. CMake auto-detects these locations:

- `./JUCE` inside this repository
- `./juce` inside this repository
- `../JUCE` next to this repository
- `~/dev/JUCE`
- the `JUCE_SOURCE_DIR` environment variable

If you put JUCE in one of those folders, this should be enough:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DQUADTABLE_REQUIRE_JUCE=ON
cmake --build build --config Release
```

If JUCE is somewhere else, pass the path explicitly:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DQUADTABLE_REQUIRE_JUCE=ON -DJUCE_SOURCE_DIR=/path/to/JUCE
cmake --build build --config Release
```

If your network allows GitHub access, CMake can fetch JUCE instead:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DQUADTABLE_FETCH_JUCE=ON -DQUADTABLE_REQUIRE_JUCE=ON
cmake --build build --config Release
```

The VST3 target is generated by JUCE under the CMake build directory when JUCE is available. The current UI is still JUCE's generated generic parameter editor, not a custom synth panel yet.

### Windows / Git Bash notes

If CMake prints `Running 'nmake' '-?' failed` or `CMAKE_CXX_COMPILER not set`, CMake picked the NMake generator but you are not inside a Visual Studio Developer Prompt. Use one of these options from the QuadTable repository folder, not from the JUCE folder:

#### Option A: Visual Studio generator

```bash
cd ~/dev/QuadTable
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DQUADTABLE_REQUIRE_JUCE=ON -DJUCE_SOURCE_DIR=$HOME/dev/JUCE
cmake --build build --config Release
```

#### Option B: Ninja generator

Install Ninja and make sure a compiler is available, then run:

```bash
cd ~/dev/QuadTable
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DQUADTABLE_REQUIRE_JUCE=ON -DJUCE_SOURCE_DIR=$HOME/dev/JUCE
cmake --build build --config Release
```

The prompt in the error showed `~/dev/JUCE (master)`, which is the JUCE checkout. The `cmake -S .` command must be run from this plugin repository, while `JUCE_SOURCE_DIR` points to the JUCE checkout.
